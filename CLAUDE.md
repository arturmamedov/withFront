# CLAUDE.md

Guidance for AI agents and contributors working in this repository.

## What this project is

**withFront** is a personal front-end tools/boilerplate library — a curated
collection of reusable jQuery snippets, CSS utility helpers, and plugin
configurations the author drops into every project. It is **not** an
application; it is a distributable library published to npm (`withfront`) and
Bower (`withFront`), with a live demo/docs site at
<https://arturmamedov.github.io/withFront/> (served from `index.html`).

- **Stack:** plain ES5 JavaScript on **jQuery 3.x**, CSS on **Bootstrap** — it
  supports **both Bootstrap 3 and Bootstrap 4** via bridge stylesheets.
- **Build tool:** **Grunt** (no webpack/rollup/bundler, no transpiler, no
  framework).
- **License:** MIT. Author: Artur Mamedov.
- Comments, docstrings, and some default UI strings mix **English and Italian**.
  This is expected; keep the surrounding language when editing a file.

## Build & commands

Everything is built with Grunt. Install deps first, then build:

```bash
npm install
npx grunt            # default build: copy + cssmin + uglify  (== npm run prod)
```

npm script shortcuts (see `package.json`):

| Command | Runs | Purpose |
|---|---|---|
| `npm run prod` / `npm run production` | `grunt` | full production build |
| `npm run dev` | `grunt -v` | verbose build |
| `npm run development` | `grunt -vvv` | very verbose build |
| `npm run onlycss` | `grunt cssmin` | rebuild CSS bundles only |
| `npx grunt watch` | watch task | rebuild on `js/**` and `css/**` changes |
| `npm test` | — | **no tests exist**; this just prints an error and exits 1 |

There is **no test suite, linter, or CI** in this repo. "Verifying" a change
means rebuilding with `grunt` and checking the output in `index.html` (the demo
page) in a browser.

The default task is `grunt.registerTask('default', ['copy', 'cssmin', 'uglify'])`.

## Architecture: source of truth vs. generated files

This is the single most important thing to get right. Several files in the repo
are **generated build artifacts that are committed to git** — editing them by
hand is pointless because the next `grunt` run overwrites them.

**DO edit (source of truth):**
- `js/**/*.js` — the individual feature modules
- `js/withplugins_concat_template.js` — the assembly template (see below)
- `withstyle.css` and `css/**/*.css` — the CSS entry point and partials

**DO NOT hand-edit (generated by `grunt`, will be clobbered):**
- `withplugins.js` (repo root) — produced from the template by `copy:build`
- everything under `dist/` — `dist/js/w-plugins.js`, `dist/js/w-plugins.min.js`,
  `dist/css/w-style.min.css`, `dist/css/libraries.min.*`, `dist/js/libraries.min.js`,
  webfonts, flags, and all `.map` files

### The `withInclude` template mechanism

The root `withplugins.js` is **assembled**, not written. `gruntfile.js` defines a
custom `withInclude()` processor used by the `copy:build` task. It scans
`js/withplugins_concat_template.js` for tokens like:

```js
/* withInclude('js/core/w-core.js') */
```

and replaces each token with the full contents of that file. The template
controls **load order** and **which modules ship** — modules whose token is
inside the `$(document).ready(function () { ... })` block run on DOM ready;
those outside run immediately. A `notInclude('...')` token is intentionally
excluded. (`asJsString` is a supported option that escapes quotes/newlines.)

**To add a new JS feature to the bundle:**
1. Create `js/<category>/w-yourfeature.js` (follow the conventions below).
2. Add a `/* withInclude('js/<category>/w-yourfeature.js') */` token to
   `js/withplugins_concat_template.js`, in the right place (inside
   `$(document).ready` for DOM-dependent code, respecting dependency order).
3. Run `npx grunt` to regenerate `withplugins.js` and `dist/`.

> Gotcha: `gruntfile.js` also defines a `concat` task with `js`/`jsfull` file
> lists. **That task is dead code** — it is not part of the `default` task and
> is documented as "not used at the moment." The real build path is
> `copy:build` + the template. Do not edit the `concat` lists expecting them to
> affect the build.

### What the default build produces

- `copy:build`: `js/withplugins_concat_template.js` → `withplugins.js` (root)
- `copy:js_src`: `withplugins.js` → `dist/js/w-plugins.js`
- `uglify:target`: `withplugins.js` → `dist/js/w-plugins.min.js` (`drop_console`, source map)
- `cssmin:wstyle`: `withstyle.css` → `dist/css/w-style.min.css` (source map; inlines `@import`s)
- `cssmin:libraries` / `uglify:libraries`: bundle vendor deps from `node_modules`
  (Bootstrap, FontAwesome, bootstrap-datepicker, slick, js-cookie, nicescroll)
  → `dist/css/libraries.min.css` and `dist/js/libraries.min.js`
- `copy:css_fonts` / `copy:flags11` / `copy:flags43`: FontAwesome webfonts and
  the `gb.svg` flag into `dist/`

> Note: `copy:css_src` (`withstyle.css` → `dist/css/w-style.css`) just copies the
> file without rebasing `@import` paths, so that unminified `dist` copy has broken
> imports — the **minified** `dist/css/w-style.min.css` is the real distributable.

## JavaScript conventions

- **Filename prefix `w-`** for every module (e.g. `w-filter.js`, `w-loader.js`).
- **Everything depends on jQuery** being loaded first (as must Bootstrap for
  Bootstrap-related modules).
- **Defensive guards — modules must no-op when their dependency or target markup
  is absent.** This is a core design rule ("there is a check before any action"),
  so consumers can include the whole bundle without wiring up every feature.
  Patterns used:
  - feature detection: `if ($().datepicker) { ... }`, `if (typeof Cookies != 'undefined') { ... }`
  - selector iteration that silently does nothing when empty: `$('.w-filters').each(...)`
  When adding a module, guard it the same way — never assume a plugin or element exists.
- **Opt-in via markup:** features activate off CSS classes / `data-*` attributes
  (e.g. `.withEqualHeight`/`.weh`, `.w-filters`/`.w-filter`/`data-filter`,
  `.period` for the datepicker range). Options are read from `data-*` attributes.
- **Config via `withOptions`** (defined in `js/core/w-core.js`): a global object
  with boolean feature flags (`debug`, `go2top`, `wAppearBottomButton`,
  `whatsappWeb`, `htmlNicescroll`, ...). A consumer overrides it by defining a
  global `wOptions` object **before** loading `withplugins.js`; `w-core.js` does
  `$.extend(withOptions, wOptions)`.
- **Debug logging via `clog(text)`** (also in `w-core.js`) — a `console.info`
  wrapper gated on `withOptions.debug`. Use `clog()` instead of raw `console.*`;
  `uglify` strips console calls anyway (`drop_console`).
- **Global breakpoint flags** come from `js/core/w-breakpoints.js`:
  `isXs/isSm/isMd/isLg` (Bootstrap 3) and `is4sm/is4md/is4lg/is4xl` (Bootstrap 4),
  each a `window.matchMedia(...)` object (use `.matches`). Modules like
  `js/style/w-height.js` depend on these — respect declared `@dependencies` in each
  file's docblock.
- **Notifications:** call `withAlert(message, type, options)` (in `w-alert.js`);
  `$.fn.gdivMessage` is the deprecated predecessor. Some modules fall back to the
  native browser `alert()` when `w-alert.js` is not included.
- **Two different `w-cookie.js` files — do not confuse them:**
  - `js/core/w-cookie.js` → `wCookies` factory, a thin wrapper over the js-cookie
    library (`get/set/remove/getJSON`).
  - `js/form/w-cookie.js` → persists form input values into cookies (activated by
    a `.w-cookie` class).
- Docblocks document `@dependencies`, activation markup, and `data-*` options —
  read them before modifying a module, and keep them updated.

## CSS conventions

- `withstyle.css` is the **entry point**: it `@import`s the `css/**` partials and
  also defines inline utility classes. Some imports are intentionally
  commented-out (corner_ribbon, bootstrap-tabs, twitter-typeahead,
  datatable-rowreorder) — enable by uncommenting, then rebuild.
- **Static pixel spacing utilities** (this is the library's signature helper):
  - Bootstrap-3 style: `.m-t-5`, `.p-r-10`, `.m-v-20` … (direction letters
    `t/r/b/l` and `v`=vertical, `h`=horizontal).
  - Bootstrap-4 style: `.mt-50`, `.py-10`, `.mx-10` …
  - Allowed sizes: `0,5,10,15,20,25,30,35,40,50,60,70,80,90,100,150,200` (px).
  - **Gotcha:** `.p-5/.m-5/.py-5/.m-b-5`-collision values like `.m-5`, `.p-5`,
    `.py-5` were deliberately **removed** so they don't override Bootstrap 4's
    own rem-based spacing scale. Use `.m-t-5`/`.p-t-5` for the 5px case.
- **Dual Bootstrap 3↔4 support** via `css/thirdparty/bootstrap3to4.css` and
  `css/thirdparty/fontawesome47.css` bridges — changes touching spacing,
  breakpoints, or icons should stay compatible with both.
- **Social color helpers** (`css/text/social-colors.css`): `.text-{social}`,
  `.bg-{social}`, and `.gradient` families (facebook, instagram, whatsapp, etc.).
- Inline utilities in `withstyle.css` include positioning (`.relpos/.abspos`,
  `.toppos-10` …), button variants (`.btn-circle/.btn-flat/.btn-xlg`), the
  `.withAlert` toast style, and animations (`.pulse-effect`, `.w-blink`, `.on-target`).
- After editing any CSS, run `npm run onlycss` (or `grunt`) to regenerate
  `dist/css/w-style.min.css`.

## Versioning & release

- The authoritative version is in `package.json` (currently **1.6.43**) and the
  latest git commit is a `Build vX.Y.Z` commit. `bower.json` tracks it; the
  `README.md` header may lag behind — trust `package.json`.
- Release flow (as reflected in git history): bump `package.json`/`bower.json`,
  run `grunt` to regenerate `withplugins.js` + `dist/`, then commit as
  `Build vX.Y.Z`. The committed `dist/` is what npm/Bower consumers get.

## Quick gotcha checklist

- Never edit `withplugins.js` (root) or `dist/**` by hand — regenerate via `grunt`.
- To change what ships in the bundle, edit `js/withplugins_concat_template.js`
  (the `withInclude` tokens), not the `concat` task in `gruntfile.js` (dead code).
- New JS module → create the file **and** add its `withInclude` token to the
  template, then rebuild.
- Guard every module against missing plugins/markup; assume consumers include
  the whole bundle but wire up only some features.
- No tests/linter — verify by rebuilding and loading `index.html`.
- Keep Bootstrap 3 **and** 4 compatibility in mind for CSS/breakpoint changes.
